# 01 需求分析与选题记录

时间：2026-11-13
参与方式：与码道（CodeArts）多轮对话完成选题收敛与需求定义

## 一、初始意图

团队最初想法为"导购类 Agent"，向码道询问可行性。码道反馈：通用导购场景同质化严重，且官方赛题优先鼓励新疆本地产业方向（校园管理、低空经济、煤化工、能源、智慧农业、智能制造、文旅数字化）。

## 二、约束条件（团队提出，Prompt 原文要点）

1. 不要同质化的选题
2. 必须有公开可获取的数据，不购买任何商业 API
3. 只考察落地能力，输出必须可验证
4. 不要很费人力的方案（团队 3 人，比赛周期 7 天）

## 三、候选方案对比（由码道生成，团队决策）

| 方案 | 差异化 | 数据可得性 | 人力 |
|---|---|---|---|
| A 能源·光伏沙尘清洗决策 | 高（评委会少见） | NASA POWER / Open-Meteo / PVGIS 全免费 | 2 人 3 天 |
| B 低空·无人机巡检编排 | 高 | 需仿真环境，搭建耗时 | 高 |
| C 文旅·可干预行程决策 | 低（多队会做） | 公开信息可整理 | 低 |

## 四、最终选题决策

选定方案 A：光伏电站沙尘清洗与发电决策。

核心理由：
1. 沙尘污损导致发电损失、清洗有成本有停机损失、受天气窗口限制——是真实的、可算账的运维决策问题
2. 决策结果可以用钱量化（净收益、回本周期），落地能力可直接验证
3. 理论发电量可接入欧盟 PVGIS 权威 API，参数全部可溯源

## 五、需求定义（最终版）

输入：电站装机、上次清洗天数、电价、清洗成本、数据模式（演示/实时）
输出：是否清洗、执行窗口、收益明细、每个 Agent 的判断依据与置信度
约束：零外部付费依赖；断网演示可运行；数据失败必须显式降级标注
