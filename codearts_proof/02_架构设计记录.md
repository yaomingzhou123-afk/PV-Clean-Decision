# 02 架构设计记录

时间：2026-11-13
方式：向码道提出设计约束，由码道产出架构并经两轮评审修订

## 一、设计约束（团队 Prompt 要点）

1. 多 Agent 协作必须是真实机制，不允许用随机文本模拟协作
2. LLM 只能做增强（总结），不能替代关键计算，避免不可复现
3. 冲突必须可追溯：每个 Agent 的输入、判断依据、输出都要能回放
4. 保留演示样例模式，断网可演示

## 二、总体架构（码道产出）

```
前端(零构建 SPA) ──POST NDJSON 流──▶ FastAPI
                                     │
                        orchestrator.stream_decision()
                          1. 参数校验(pydantic + validate_config)
                          2. 数据层 weather.fetch_context()
                             ├─ Open-Meteo Forecast (辐照/降水/风速)
                             ├─ Open-Meteo Air Quality (PM10/沙尘)
                             ├─ PVGIS PVcalc (权威理论发电量, 19年ERA5)
                             └─ 失败降级: 内置样例并显式标注
                          3. pv_model.compute_metrics() 确定性计算
                          4. 四个评审 Agent 独立出意见(可反对)
                          5. 评审主席汇总 → 仲裁(延后/分区) → 第二轮
                          6. llm.chat() 仅生成总结(可选,失败静默降级)
```

## 三、关键设计决策与理由

| 决策 | 理由 |
|---|---|
| 规则引擎承载全部决策计算 | 结果可复现、可解释，符合"不允许编造协商结果" |
| LLM 仅用于最终总结 | 增强可读性；失败时回退到固定话术，不影响决策 |
| Agent 意见由确定性指标推导 | 每条意见的 stance 都能追溯到 metrics 中的具体数值 |
| 天气阻塞优先于收益仲裁 | 天气不满足时任何经济方案都不可执行，避免无效协商 |
| PVGIS 管发电潜力、Open-Meteo 管作业窗口 | 气候均值定"发多少电"，三天预报定"能不能洗"，职责分离 |
| NDJSON 流式事件 | 前端逐条渲染协商过程，天然形成可回放时间线 |

## 四、Agent 职责矩阵（v3.0 七 Agent，2026-11-15 更新）

| Agent | 输入 | 判断逻辑 | 可否决情形 |
|---|---|---|---|
| Weather 气象分析官 | 未来3天预报 | 降水/风速对照安全阈值 | 降水或风速超限 → defer |
| Soiling 污损评估官 | PM10、运行天数 | 污损模型计算损失率 | 损失率 < 5% 阈值 |
| PV Performance 发电分析官 | 理论发电量、污损率 | 可恢复电量计算 | 无否决权，提供数据 |
| Economic 收益核算官 | 发电量、成本、电价 | 净收益 = 收益 − 清洗 − 停机 | 净收益 ≤ 0 → hold |
| Safety 安全否决官 | 数据质量、天气、间隔 | 三条件否决（最高优先级） | 任一触发 → 否决 |
| Critic 审查主席 | 全部 Agent 结果 | 四类审查（计算/逻辑/数据/阈值） | 计算错误/逻辑矛盾 → 驳回 |
| Decision 最终仲裁官 | 全部意见与阻塞项 | 保守序汇总（insufficient > weather > interval > economics） | 遵守保守序，不推翻 Safety |

## 五、架构演进记录

- v2（11-13）：四 Agent（气象/污损/收益/调度）+ 评审主席 + 仲裁
- v2.2（11-14）：Agent 置信度由确定性指标推导（0.6-0.99），结构化 evidence
- v3.0（11-15）：升级为七 Agent，新增 Safety（一票否决）和 Critic（四类审查），Decision 遵守保守序；新增 MCP 工具层和 Function Calling
