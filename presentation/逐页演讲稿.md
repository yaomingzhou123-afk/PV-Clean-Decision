# PV-Clean-Decision · 答辩逐页演讲稿

**总时长建议：8–10 分钟 · 语速中等 · 语气专业克制**

---

## 第 1 页 · 封面（30 秒）

> 各位评委老师好，我们团队带来的是「疆光」——PV-Clean-Decision，基于多 Agent 协作的光伏电站沙尘清洗决策智能体。这个项目解决的是新疆光伏基地一个很实际的问题：沙尘积灰导致发电损失，但清洗成本高，什么时候洗、值不值，缺乏量化决策工具。

**要点提示**：语速稍慢，先让评委看清项目名和副标题。

---

## 第 2 页 · 行业背景与痛点（45 秒）

> 新疆是光伏大省，也是沙尘频发区。PM10 常年高于 80 微克每立方米，组件积灰导致的发电损失最高可达 15%——这是我们模型的上限，不是编造的数据。但一次 20MW 电站的全站清洗要花四千元，盲目清洗就是浪费。
>
> 核心问题是三重约束：清洗收益、清洗成本、作业安全，三者怎么平衡？目前主要靠人工经验，缺乏可解释的量化决策工具。

**要点提示**：强调"可解释、可追溯"是项目与纯经验判断的本质区别。

---

## 第 3 页 · 项目解决方案（45 秒）

> 我们的方案有四个核心模块：第一，七 Agent 协作决策，七个 Agent 基于同一份数据快照独立分析，有否决、有审查、有仲裁；第二，MCP 标准工具层，JSON-RPC 协议真实接入数据源；第三，全链路数据可信，每条数据标注来源和是否模拟；第四，模拟实验室，评委可以现场改参数看策略对照。

**要点提示**：用手势指向四个卡片，不要念完文字。

---

## 第 4 页 · 系统技术架构（50 秒）

> 系统分四层。最下面是三个公开数据源：Open-Meteo 天气预报、空气质量、PVGIS 历史发电量，全部免费、免 Key。往上是 MCP 工具层，JSON-RPC 2024-11-05 协议，三个工具：拉取站点数据、检索知识库、计算经济性。再往上是七 Agent 决策层，Safety 有三条件否决权，Critic 有四类审查权，Decision 遵守保守序仲裁。最上面是前端驾驶舱，原生 HTML/CSS/JS 零依赖。
>
> 工程上：206 项 pytest 全绿，GitHub Actions 持续集成，13 个 REST 接口加 2 个流式接口。

**要点提示**：从下往上指着架构图讲，强调"四层独立、接口清晰"。

---

## 第 5 页 · 多 Agent 协作（60 秒）

> 七个 Agent 各管一段：气象 Agent 判断未来 48 小时能不能作业；污损 Agent 用 PM10 和无雨天数估算发电损失；发电 Agent 分析潜在损失；经济 Agent 算清洗值不值；安全 Agent 检查用户配置的阈值，风速超限或数据降级就一票否决；Critic Agent 审查计算是否一致、有没有把模拟数据说成实时、单位是否正确；决策 Agent 汇总后输出最终结论。
>
> 关键：这不是展示层。每个 Agent 是真实执行的 Python 函数，读取统一的 metrics，输出结构化结果。Critic 发现计算错误会 reject，决策 Agent 收到 reject 后阻止清洗——这个机制有 28 项专项回归测试覆盖。

**要点提示**：这是技术核心页，可以多停留几秒，强调"真实执行"和"双否决"。

---

## 第 6 页 · 核心算法（50 秒）

> 积灰用线性累积模型：基础速率千分之四每天，PM10 超过 80 微克后每增加 1 微克日污损速率增加万分之三点五，上限 15%。注意：所有输出都标注 method=model_estimate，不是传感器实测。
>
> 经济性公式：有效可恢复损失等于污损率乘以恢复效率 0.95 再乘以自然清洁折减；日增量收益等于理论日发电量乘以有效损失乘以一千乘以电价；净收益等于日增量收益乘以评估周期，减清洗成本和停机损失。
>
> 敏感性分析是单因素确定性扰动，12 个场景，每次只改一个参数完整重算，不做蒙特卡洛，不编造置信概率。

**要点提示**：公式部分放慢，让评委看清每个系数的来源标注。

---

## 第 7 页 · 清洗经济性决策（45 秒）

> 系统输出四种决策：建议清洗、建议延后、暂不清洗、数据不足。优先级是保守序：数据不足大于天气安全，大于最小间隔，大于经济性。
>
> 实测 demo 场景：20MW 电站、距上次清洗 20 天、PM10 135、电价两毛五、清洗成本四千元——净收益三万九千四百七十八元，回本一点二天，建议清洗。
>
> 如果净收益为负，系统会输出暂不清洗；如果未来降雨超阈值，会输出建议延后；如果关键数据源降级，会输出数据不足——不会用模拟数据编造一个清洗结论。

**要点提示**：四个大数字（39,478 / 1.2 / 15.0 / 95.1）要突出。

---

## 第 8 页 · 数据来源与可信度（45 秒）

> 三个数据源全部公开免费。Open-Meteo 天气预报提供辐照、降水、风速；Open-Meteo 空气质量提供 PM10 和沙尘；PVGIS 用 ERA5 2005 到 2023 年历史气候均值提供理论发电量，标注为 historical 非实时。
>
> 每条数据有九个元数据字段，前端数据质量面板逐条展示。live 模式下关键源一旦降级为模拟样例，系统直接输出数据不足，不用模拟数据做真实决策。导出报告的数据来源是按实际记录动态生成的，不会把 demo 模拟数据写成 Open-Meteo。

**要点提示**：这是可信度页，语气要坚定，强调"诚实标注"是设计原则。

> 这是系统真实运行的截图。左边是决策驾驶舱：点运行决策后，七个 Agent 在时间线里逐个出现，每个给出结论、证据、数据源、假设和不确定性；右侧是决策面板，显示结论、收益瀑布、环境指标、决策证据和数据质量。

## 第 10 页 · 三个验证场景（50 秒）

> 三个实际运行的验证场景。第一，高积灰场景：PM10 高、长期无雨，系统建议清洗，净收益三万九千元，窗口在演示 D2。第二，降雨场景：预计未来降雨八毫米，超过一毫米阈值，Safety 否决生效，建议延后——即使污损高达 15%，也不建议在降雨前清洗。第三，数据不足场景：断网时关键源降级为模拟样例，系统直接输出数据不足，页面上显示双横杠而不是零——不会编造一个清洗结论。

**要点提示**：三个场景一一对应三种决策，突出"数据不足也敢说"。

## 第 11 页 · 项目创新点（45 秒）

> 五个创新点，每个都可验证。第一，七 Agent 双否决治理链——Safety 可否决、Critic 可驳回、Decision 保守序仲裁。第二，MCP 标准协议真实实现——JSON-RPC、参数校验、读超时、幂等关闭。第三，全链路数据可信标注——九字段元数据、模拟数据金色标注。第四，模拟实验室三策略对照——同一输入同一评价周期。第五，答辩级稳定性修复——十项 P0 修复全部有回归测试覆盖。

**要点提示**：不要逐条念完，选两三条深入讲。

## 第 13 页 · 应用价值与落地前景（40 秒）

> 应用价值四个字：可解释、可追溯、可信任、可演示。每个决策有理由链和证据表，不是黑盒；从数据到数字每步可查；模拟数据诚实标注；断网断 Key 也能跑。
>
> 落地路径分四步：先接电站实测发电量校准污损模型，再接积灰传感器替换 PM10 代理，然后对接实际清洗合同价格，最后部署到运维平台按方阵输出分区计划。
>
> 坦诚说明：目前是比赛原型，未接入真实电站数据，未产生真实收益。

**要点提示**：最后一句要诚实，这是加分项不是减分项。
